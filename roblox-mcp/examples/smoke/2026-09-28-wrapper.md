# Smoke: --wrap-studio with Claude Code (2026-09-28)

Claude Code 2.1.283, `claude -p`, one MCP server: roblox-mcp with `--wrap-studio`
wrapping `tests/fixtures/fake_studio_mcp.py` (Studio's documented tool names; tools echo
what they receive). User plugins disabled, no skill installed. Game: a copy of
`tests/fixtures/sample_game` (Rojo).

**Run 1**: "change the Damage module with multi_edit ... then create an anchored red
part named Marker in Workspace with execute_luau". The agent listed studios, read the
script, and sent two Edit-mode `execute_luau` calls; both reached the child wrapped in a
`ChangeHistoryService` recording (the agent sent `datamodel_type: "edit"`, lowercase).
It didn't call `multi_edit`: the fake's `script_read` returned only an echo, and the agent
refused to edit blind. (The fake now also returns a source.) Side effect seen: a read-only
Edit-mode call (`return ...Source`) gets wrapped too, adding an empty undo step at most.

**Run 2**: "change the Damage module (game.ReplicatedStorage.Shared.Damage) with
multi_edit so apply() also rounds the result down":

1. `list_roblox_studios` → `script_read` (studio s1)
2. `multi_edit` → refused: "game.ReplicatedStorage.Shared.Damage is synced by Rojo from
   src/shared/Damage.luau; edit that file (then check_code). A Studio edit would be
   overwritten on the next sync."
3. read `src/shared/Damage.luau`, `Edit` → `return math.floor(math.max(0, health - amount))`
4. `check_code` → 0 errors, 0 warnings

Final answer: "multi_edit … was rejected … I made the change in src/shared/Damage.luau
instead … I haven't confirmed that the live Studio session has picked up the change
through Rojo sync."
